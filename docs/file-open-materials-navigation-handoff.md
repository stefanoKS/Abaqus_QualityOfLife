## A. Fix the owner of a newly created or opened file

**Cause.** `FileBar.tsx:newModel` posts to `/api/projects` with no group. `services/api/main.py:create` checks archive status only for an explicit group. In `services/store.py:append_revision` an omitted group falls through to `legacy_group(db)`, which selects “Imported projects” by its mutable display name regardless of archive status. `services/portable_files.py:open_model` uses the same fallback through `store.save`. Both model-open endpoints reach it. `Workspace.tsx` correctly honors both archive flags, and the backend correctly refuses edits after creation.

1. Give independently opened/created files persistent ownership distinct from the historical migration group. Prefer an explicit file-document owner or ownership type with a stable identity. Reuse the SQLite working-head and queue mechanisms. Keep household/project display names out of owner selection. If using an internal group, exclude it from user archive/delete controls and enforce those restrictions in the API. A global change to the legacy fallback also affects duplication, result imports, older API clients and migration. Audit those callers individually.
2. Resolve and validate ownership in the same SQLite write transaction as head creation. Keep explicit creation in an archived group rejected. Cover simultaneous creates and an archive racing with a group-based create. A successful standalone File action must return an editable head, including after restart.
3. Preserve archive state and history, including existing models accidentally created under the archived group. Provide a deliberate way to recover an existing model as an independently editable copy. Reopening a saved `.aqmodel` is one such path after the fix. An untitled stranded model also needs a path from archived history. Keep originals, submitted setup replays and result files read-only. Never infer which older models to move from the group name or “Untitled”. As a current workaround for a new model, explicit creation inside a different, active project succeeded and the following edit returned HTTP 200 with the legacy group still archived.

**Gate A.** Use Edge against a real disposable API. Create an existing model, archive its group, then click the actual New button.
